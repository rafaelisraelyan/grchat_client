# Windows updater R1

ZIP подписывается существующим Ed25519-ключом обновлений. Клиент проверяет подпись до распаковки. SHA-256 sidecar при наличии добавляет проверку целостности. Архив должен содержать grchat_client.exe, flutter_windows.dll, data/icudtl.dat, data/flutter_assets и остальные DLL штатной Windows-сборки. ProductVersion EXE должен соответствовать основной версии выбранного тега. Стадия сборки проверяется локально на фиктивном приложении, отдельно от публикации.

Обновление распаковывается в соседний каталог *.grchat-stage-<попытка>. После проверки структуры и версии скрипт ждёт завершения запускающего процесса и просит закрыться другие процессы только из этого каталога установки. Заблокированный каталог останавливает активацию. Две попытки активации исключаются файловой блокировкой. Затем текущий каталог сохраняется как *.grchat-backup-<попытка>, а staging переносится на его место. Это две операции переименования, между ними возможна пауза. Короткая проверка после запуска подтверждает, что приложение не завершилось в первые четыре секунды.

При ошибке активации скрипт сохраняет неудавшийся кандидат и возвращает старый каталог. Если вмешались блокировки, питание или антивирус, сохранившийся backup можно вернуть вручную. Закройте процессы конкретной установки и запустите созданный apply.ps1 с -Recover. Путь к скрипту записывается в диагностике клиента до переключения. Если скрипт недоступен, после проверки путей переместите сломанный каталог в отдельное место и переименуйте каталог соответствующей резервной копии обратно. Сохраняйте предыдущую копию до проверки новой версии. Для установки нужен доступ записи к родительскому каталогу и место для распаковки рядом с текущей установкой.

До публикации сверяйте архив, подпись, commit и версию из ресурса EXE. Отдельная проверка нужна для recovery после остановки процесса между переносами и для установок под управлением внешнего упаковщика.
