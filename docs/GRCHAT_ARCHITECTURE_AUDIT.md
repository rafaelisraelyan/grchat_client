# Архитектурный аудит проекта GRChat

> Исторический срез. Актуальный транспорт, матрица совместимости и уровни приёмки описаны в [архитектуре R1](architecture-r1.md).

## 1. Executive Summary

Проект GRChat - это кроссплатформенное приложение для общения, объединяющее возможности мессенджера, серверов, каналов и голосовой/видеосвязи. Приложение реализовано на Flutter с использованием Riverpod для управления состоянием.

Текущее состояние проекта показывает хорошо структурированную архитектуру с четким разделением ответственности между модулями. Все основные компоненты функционируют корректно, включая систему вызовов с поддержкой WebRTC, безопасную аутентификацию, медиа-обработку и управление сетевыми соединениями.

## 2. Architecture Overview

### Основные компоненты

1. **UI Layer** - Flutter интерфейс с использованием Riverpod для управления состоянием
2. **Business Logic Layer** - Основная логика приложения в модулях `auth`, `chat`, `call`
3. **Transport Layer** - Сетевое взаимодействие через WebSocket с поддержкой подписей и шифрования
4. **Media Layer** - Обработка медиа-ресурсов для звонков с использованием WebRTC

### Связи между компонентами

- UI взаимодействует с Business Logic через Riverpod providers
- Business Logic использует Transport Layer для сетевых операций
- Call модуль интегрируется с Media Layer для управления камерой и микрофоном
- Все модули зависят от общего `app/providers.dart` для управления состоянием

## 4. Calls & Media

### Архитектура звонков

Проект реализует сложную систему звонков с использованием WebRTC. Основные компоненты:

1. **ActiveCall** (`lib/src/call/call_state.dart`) - Основной класс для управления активным звонком
2. **CallPhase** - Состояния звонка (ringing, active)
3. **ReconnectWatch** - Машина состояний для восстановления соединения (см. `reconnect_watch.dart`)
4. **CameraLock** - Защита от конфликтов при использовании камеры между экземплярами
5. **CameraBlock** - Система блокировки камеры при конфликте (см. `camera_notice.dart`)

### Жизненный цикл звонка

1. **Инициализация** - Создание экземпляра ActiveCall
2. **Подключение** - Установка WebSocket соединения и начальная инициализация
3. **Получение SDP** - Обмен сигнализацией WebRTC
4. **Конфигурация медиа** - Настройка камеры и микрофона
5. **Активный звонок** - Передача медиа данных
6. **Завершение** - Освобождение медиа ресурсов и завершение соединения

### Защита от race conditions

Проект реализует несколько механизмов защиты от гонок:

1. **Epoch Guard** (`call_state.dart:211-215`) - Защита от использования устаревших медиа потоков
2. **CameraLock** (`camera_lock.dart`) - Потокобезопасное управление камерой
3. **ReconnectWatch** (`reconnect_watch.dart`) - Машина состояний для восстановления соединения с защитой от дубликатов

## 6. Technical Risks

| Риск | Серьезность | Обоснование | Место в коде |
|------|-------------|-------------|--------------|
| Потенциальные проблемы с WebRTC в разных средах | Высокая | Различные реализации WebRTC могут вызвать несовместимость | `call_state.dart`, `media_session.dart` |
| Утечка памяти при многократных вызовах | Средняя | Необходима тщательная проверка освобождения медиа ресурсов | `call_state.dart`, `camera_lock.dart` |
| Проблемы с поддержкой нескольких одновременных вызовов | Средняя | В текущей реализации не проверено поведение при одновременных вызовах | `call_session.dart` |
| Зависимость от определенных версий зависимостей | Низкая | Зависимости могут устареть со временем | `pubspec.yaml` |
| Проблемы с производительностью в режиме фонового вызова | Средняя | Не реализована оптимизация для фонового режима | `call_state.dart` |
| Ограничения по количеству одновременных вызовов | Высокая | Ограничения в архитектуре WebRTC | `group_call.dart` |
| Проблемы с восстановлением соединения | Средняя | Сложность реализации полного восстановления в сложных сетевых условиях | `reconnect_watch.dart` |
| Неэффективная обработка ошибок в медиа-потоках | Средняя | Может привести к зависаниям | `call_state.dart` |
| Зависимость от конкретной реализации Desktop API | Средняя | Может вызвать проблемы при переходе на другие платформы | `desktop/` |
